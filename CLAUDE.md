# Project notes

Personal desktop-browser 가계부 (household ledger). UI copy is Korean; code and comments are English.

- **Money model** (see the comment at the top of `src/db/schema.ts`): every transaction belongs to a wallet; transfers move money between wallets; card bill payment is a bank → card transfer, never an expense. Balances are computed (`opening_balance + transactions`), never stored.
- **Dates** are `YYYY-MM-DD` strings in KST. Use `todayKST()` from `src/lib/dates.ts`, never `new Date().toISOString()`.
- **Data access**: every exported function in `src/server/queries.ts` and `src/server/actions.ts` calls `requireUser()` itself and scopes by `user_id`. Actions validate with Zod, check wallet/category ownership, and call `refresh()`. `actions.ts` is `'use server'`, so it exports only async functions and types; shared constants live in `src/lib/`. Every record list goes through one row builder (`TransactionRow`) whose order ends on the id, so ties never reshuffle.
- **Review queue (확인할 것)**: `transactions.reviewReason` (`ai` | `new_place` | `uncategorized`), `reviewedAt` and `sourceText` (the line typed in quick entry). A record is pending while it has a reason and no `reviewedAt`. `createTransaction` derives the reason on the server from `origin` (`form` | `quick` | `ai`) with `deriveReviewReason` in `src/lib/review.ts`; quick entry passes `origin` and `sourceText`. `new_place` compares `placeKey(memo)` with its SQL twin in `actions.ts`, and both must split on exactly JS `\s`. Confirm with `confirmTransaction` (undo `unconfirmTransaction`), edit inline with `patchTransaction` (changed fields only), and undo a delete with `restoreTransaction`, which brings the row back with the same id, createdAt and review state. The toasts live in `src/components/transactions/notify.ts`.
- **Cache Components is on.** Pages render a `<Suspense>` boundary and read session/searchParams inside it. Call `await connection()` before using the clock in a server component.
- **Drizzle gotcha**: single-table selects render columns unqualified (`"id"`), so correlated subqueries must reference outer columns with `sql.raw('"table"."col"')`.
- **Shortcuts** go through `src/lib/hotkeys.ts`; `hotkeyName` reads `event.code`, so letters work with the Korean IME on. `useHotkeys` listens on `document`, so a page's keys run before UIProvider's global ones; a handled key is `preventDefault()`-ed and the global handler skips it (⌘K excepted, which never opens over another dialog). A widget that cancels a key only to stop its own default (the detail pane's closed Select typeahead) calls `passKeyToShortcuts()`, so the key still reaches the shortcuts. Chords (`G D/T/W/C`) keep their state in `hotkeys.ts`, and page keys stand aside while one is pending. `/` focuses the page's `[data-page-search]` input if it has one, else opens the palette. Nothing fires under an open overlay, and Backspace/Delete/Enter/Space belong to a focused button, link, tab or combobox. Every shortcut has a visible `<Kbd>` hint somewhere.
- **Design direction**: the user rejected the earlier paper/bento look and a HeyMoa-style pastel + sticky-note look, and chose board P (a Ramp-style three-pane inbox). Improve within P; ask before restyling.
- **Shell**: a warm dot-grid page (`page-grid`) frames one white app window (16px inset, radius 16 and the only window shadow from 1024px up). Inside it: a 56px top bar and a 64px icon rail, separated by hairlines (`border-line`, `border-line-soft`), never shadows; only overlays get `shadow-overlay`. Pages render into `<main data-slot="app-main">`, which never scrolls. By default the page root becomes a padded 1240px scroll column; a page with its own panes uses `<FullBleed>` from `src/components/common.tsx`, and each pane scrolls itself (`min-h-0 overflow-y-auto`). Pane headers and empty states use `PaneHeader` and `EmptyState` from the same file.
- **Design language**: ink `#141414` carries text and primary buttons. The lime `signal` `#e4f222` is the only accent, kept for the one key action or status on a screen (확인, pending dots, count badges), always with ink text on it. Inside the window, selected rows, chips and tracks use `bg-muted`; `bg-page` is only the frame. Money: expenses are ink with `−`, income is `text-income` green with `+`, transfers ink-3 with no sign (`<Amount>`). Category colors from the DB only tint small icon tiles. Pretendard only: `.display` (Pretendard 800, tabular) for big amounts and `<BigWon>`, `.num` for list numbers. Radius ladder: chips 5–8px, controls 9–10, cards 12, overlays 14, window 16. Controls are at least 40px tall (44 for primary actions). Tokens for light and dark live in `src/app/globals.css`; don't hard-code colors outside them. Charts use ink tints and square-root scales so one big day (rent) doesn't flatten the rest. Particles: use `josa()` from `src/lib/josa.ts` when a sentence wraps a data value.
- **Icons**: Phosphor, regular weight in UI chrome (never emoji there) and duotone on category-tinted tiles (`src/components/icons.tsx`). Categories store an emoji; known emojis map to a Phosphor icon, anything else renders the emoji. No generated raster art: the user rejected AI-made 3D clay images as looking "too AI". The logo is `public/logo.svg` / `<LogoMark>` (near-black tile, lime receipt glyph); the login visual is built from real UI components.
- **AI quick entry** (`src/server/ai.ts`): only offered when the rule parser isn't confident (`aiReason` in `src/lib/ai-entry.ts`), run with ⌘Enter. Wallets and categories go to the model as short refs (`W1`, `C3`) constrained by a Zod enum schema (`client.beta.messages.parse` + `betaZodOutputFormat`), then `normalizeAiTransactions` re-checks everything. Model from `AI_MODEL` (default `claude-opus-5-5`, effort `low`, server-side refusal fallback where supported). Needs `ANTHROPIC_API_KEY` in `.env.local`; without it the AI button is disabled and nothing else changes.
- If styles look stale in `next dev` (Turbopack sometimes keeps an old `globals.css`), stop the server, delete `.next/dev`, and restart.
- Local DB: `docker compose up -d` (Postgres on 5433). After schema changes: `npm run db:generate && npm run db:migrate`.
- Check before finishing: `npm run typecheck && npm run lint && npm test && npx next build`.
